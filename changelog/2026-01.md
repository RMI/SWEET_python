# SWEET_python Changelog — January 2026

**Highlights:** This month's work moved TRACE city loading into the WasteMAP data flow: the city-parameter loaders were realigned with WasteMAP's input columns and reference year, made DST-aware, and given a 2025 backfill path. The advanced decision-support (ADST) modeling path also gained per-scenario growth handling, biocover-based oxidation floors, and open/close windowing of new-landfill waste masses.

## Added
- New `WasteGeneratedDF.create_advanced_2` builder for the advanced DST path: it grows a per-component waste-mass DataFrame using separate baseline and scenario population data-collection years, and optionally re-grows everything from an `implement_year` onward using the scenario year. The advanced path in `city_params.py` now calls this instead of the old single-year `create_advanced`. ([#11](https://github.com/RMI/SWEET_python/pull/11))
- A `backfill` mode on `load_andre_params` that rebuilds a city's parameters from its 2025 (`Year Emissions == 2025`) row, including net-mass validation that aborts the load if input problems are detected or any net mass goes negative. ([#9](https://github.com/RMI/SWEET_python/pull/9))
- An `iso3` country code is now included in the parameter dictionary returned by the advanced city builder. ([#10](https://github.com/RMI/SWEET_python/pull/10))
- A biocover oxidation floor in the advanced path: where a biocover value is set, the model now raises oxidation values up to that floor (baseline across all years; scenario only from the implement year onward). ([#10](https://github.com/RMI/SWEET_python/pull/10))

## Changed
- `load_csv_new` now reads a single passed-in city row (rather than indexing the database by city name) and takes a `dst` flag; in DST mode it skips the "Uses Sites Method" branch. Diversion fractions are also filled with 0 where missing. ([#9](https://github.com/RMI/SWEET_python/pull/9))
- The waste-composition reference year used in `CityParameters` (the metal/glass/plastic/other/rubber, wood/paper/textiles, and food/green breakdown sums) was moved from 2000 to 2025 to match current TRACE/WasteMAP input data. ([#9](https://github.com/RMI/SWEET_python/pull/9))
- The `div_component_fractions` field on `CityParameters` was widened to also accept a plain DataFrame or a dict of DataFrames. ([#9](https://github.com/RMI/SWEET_python/pull/9))
- In the advanced path's TRACE-derived branch, new-landfill waste-mass series are now zeroed after each landfill's close year (baseline and scenario). ([#10](https://github.com/RMI/SWEET_python/pull/10))
- The new-landfill mass windowing was completed: the TRACE-derived branch now also zeroes masses before each landfill's open year, and the series-based branch zeroes masses both before the open year and after the close year, for baseline and scenario alike. ([#12](https://github.com/RMI/SWEET_python/pull/12))
- The default site open year (used when no site date is supplied) was changed from 2010 to 1990. ([#12](https://github.com/RMI/SWEET_python/pull/12))
- The `fraction_of_waste_vector` series is now constructed as float (`0.0`) to avoid an integer-dtype series. ([#10](https://github.com/RMI/SWEET_python/pull/10))

## Fixed
- Corrected the misspelled input-column keys `Diversons:` → `Diversions:` (Compost, Anaerobic Digestion, Incineration, Recycling) in both the legacy `load_from_csv` and the `load_csv_new` loaders, so diversion percentages read from the correct WasteMAP columns. ([#9](https://github.com/RMI/SWEET_python/pull/9))

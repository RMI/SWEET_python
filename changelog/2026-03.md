# SWEET_python Changelog — March 2026

**Highlights:** This month focused on wiring the City model into the WasteMAP TRACE pipeline. Callers can now pass precipitation/temperature directly on each site to bypass the database weather lookup, the remaining DB weather query gained transient-error retries with backoff, and several waste-window and reference-year bugs in the TRACE/SDST ingestion path were fixed.

## Added
- City model now accepts caller-provided `precipitation`/`temperature` on the input row (dict, Series, or 1-row DataFrame) and treats them as authoritative, skipping the database weather query entirely when either key is present — even if the value is NaN. This lets the TRACE pipeline, which already joins weather onto each site, avoid a per-site DB round trip. ([`2d61ecf`](https://github.com/RMI/SWEET_python/commit/2d61ecf))
- Weather DB lookup is now resilient to transient connection failures: it retries up to `DB_QUERY_MAX_ATTEMPTS` (default 5) with exponential backoff, recognizing SSL/EOF/connection-reset/recovery-mode errors as transient, and applies a configurable statement timeout, connect timeout, TCP keepalives, `pool_pre_ping`, and pool recycling (all tunable via `DB_*` environment variables). ([`e4e21f5`](https://github.com/RMI/SWEET_python/commit/e4e21f5))

## Changed
- Reference years for waste and population data are now derived dynamically instead of hardcoded to 2024. When a site has no `incoming_waste_year`, the model uses the previous calendar year, or `close_year - 1` for sites that closed before that reference year; population data year now mirrors the waste-data year rather than being pinned to 2024. ([`a4be48a`](https://github.com/RMI/SWEET_python/commit/a4be48a))
- Location parsing for the TRACE use case is more robust: the model first tries a `location` geometry, then top-level `longitude`/`latitude` columns (Series), then falls back to the first row of a DataFrame for backward compatibility. ([`e4e21f5`](https://github.com/RMI/SWEET_python/commit/e4e21f5))
- The weather SQL query was restructured to filter on `weather_type` and apply a bounding-box (`&&`) pre-filter before the `ST_Intersects` spatial check, improving the spatial join for precipitation/temperature averaging. ([`e4e21f5`](https://github.com/RMI/SWEET_python/commit/e4e21f5))
- When weather is unavailable, `precip_zone` is now set to `None` instead of `np.nan` across the ingestion paths, keeping the precipitation-zone field consistent with downstream lookups. ([`2e97be7`](https://github.com/RMI/SWEET_python/commit/2e97be7))

## Fixed
- New-landfill scenario builder no longer overwrites pre-implementation years with the baseline waste-mass slice; the scenario series now correctly retains its own masses for years before `implement_year`. ([`a80ea77`](https://github.com/RMI/SWEET_python/commit/a80ea77))
- Landfill active-window mask now excludes the close year (`open_date:close_date-1`) so a site is not counted as receiving waste in the year it closes. ([`2588914`](https://github.com/RMI/SWEET_python/commit/2588914))
- SWEET model year range is clamped to start no earlier than 1990 (`max(open_date, 1990)`), preventing the first-order-decay loop from generating spurious pre-1990 years for sites with very early open dates. ([`2588914`](https://github.com/RMI/SWEET_python/commit/2588914))

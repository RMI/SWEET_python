# SWEET_python Changelog — October 2026

**Highlights:** A site in the city-level advanced DST can state its own decay
rate and oxidation rate, and a new call reports the rates the model would use
at each site that states none. No request that leaves them out changes.

## Added

- **A city-level advanced DST site can state its own `k` and oxidation rate.**
  `CityLandfillSpec` gains `k_override` and `oxidation_override`, the site DST's
  `ks_overrides` and `oxidation_override` for one landfill. Each is optional and
  per year. When it's left out, the model works the rate out exactly as before.
  - `k_override` (1/yr, 0 or more) replaces the k the model derives from the
    city's temperature, precipitation and composition. It applies to every
    biodegradable component and only to the site that states it.
  - `oxidation_override` (0 to 1, or null) is the site's oxidation that year,
    used as stated. It replaces both the factor looked up from the site's type
    and gas capture and the `biocover` floor, so a stated rate can sit below a
    cover's. A null year states nothing and gets the lookup and the floor as
    before. That is how a caller hands a year back to the model, for example
    once an intervention has changed the site the rate was stated for.
  - Out-of-range values are refused with `invalid_parameters`, naming the field
    and the year. They are not clipped. Only oxidation takes null years.
  - `dst_common.oxidation_series` takes the override as an optional `override`
    series, NaN where nothing is stated. `dst_common.optional_variant_series`
    reads a `{year: value or null}` input, with a gap following the year
    before it as every yearly input does, and a null carried rather than filled
    over.

- **`run_advanced_dst_city_defaults` reports each site's own rates.** It takes the
  same request as `run_advanced_dst_city` and returns, per variant and per site,
  the `k` and the oxidation factor the model uses where no override is given.
  The oxidation factor is the type-and-capture lookup raised to the request's
  `biocover` floor, which is exactly what a year of `oxidation_override`
  replaces. It runs no decay, so a caller can show the
  defaults beside the boxes a user types into on every edit. Fed back in as
  overrides, the defaults reproduce the plain run bit for bit, and a test holds
  them to that.
  ([#88](https://github.com/RMI/SWEET_python/pull/88), [RMI/WasteMAP#883](https://github.com/RMI/WasteMAP/pull/883))

# SWEET_python Changelog — April 2026

**Highlights:** This month hardened the single-site decision-support (SDST) path against pandas dtype and baseline/scenario alignment bugs, and added PM2.5/PM10 particulate emission outputs derived from methane destroyed by flaring. Two of the SDST fixes were committed directly to `main` (no PR) and are linked by commit.

## Added
- PM2.5 and PM10 particulate emission outputs: the monthly SWEET model now derives particulate mass (kg/month) from the methane destroyed by flaring using fixed emission factors (0.00024 kg PM per m^3 CH4 flared, the same factor for both PM2.5 and PM10), and `Landfill` exposes the results as `pm2p5_kg_monthly` / `pm10_kg_monthly`. The attributes default to `None` for the non-monthly (`estimate_emissions2`) path and are guarded so callers can treat missing values as zero. ([#16](https://github.com/RMI/SWEET_python/pull/16))

## Changed
- Reworked how the SDST path builds baseline and scenario oxidation series: the baseline series is constructed first (with oxidation-override and biocover-floor adjustments applied to it), then copied into the scenario so baseline and scenario stay identical for all years before the implementation year, with scenario changes applied only from the implementation year onward. Oxidation override and biocover values are now cast to float. ([`ef82f24`](https://github.com/RMI/SWEET_python/commit/ef82f24))
- SDST site-type selection now reads the site type directly from the canonical landfill row's `type` field, falling back to the region-based default (Sanitary Landfill vs. Dumpsite) only when that value is missing or blank. ([#16](https://github.com/RMI/SWEET_python/pull/16))
- The monthly and `estimate_emissions2` model paths now subset the incoming waste-mass DataFrame to the city's defined waste components, guarding against extra or misaligned columns. ([#17](https://github.com/RMI/SWEET_python/pull/17))
- Weather lookup is now best-effort: an unreachable weather database is logged and the model falls back to default weather values instead of raising an HTTP 500. ([`ce36752`](https://github.com/RMI/SWEET_python/commit/ce36752))

## Removed
- Removed a redundant `await conn.close()` in the weather lookup that ran after the connection had already been closed in the cleanup block. ([`ce36752`](https://github.com/RMI/SWEET_python/commit/ce36752))

## Fixed
- Fixed pandas integer-upcast errors in the SDST/DST oxidation handling by making the `Dumpsite` oxidation and gas-capture-efficiency defaults floats (`0.0` instead of `0`) across the DST/SDST blocks and forcing the baseline oxidation series to float dtype, so fractional oxidation factors (e.g. biocover oxidation of 0.5) are preserved. ([`ce36752`](https://github.com/RMI/SWEET_python/commit/ce36752))
- Fixed pre-implementation-year scenario waste masses in the SDST path so they are copied from the baseline series rather than being re-assigned to themselves, ensuring scenario waste mass equals baseline before the implementation year. ([#15](https://github.com/RMI/SWEET_python/pull/15))

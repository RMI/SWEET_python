# SWEET_python Changelog — February 2026

**Highlights:** Refactored the Singapore (Wang et al. 2024) k-value calculation
into its own subpackage, hardened data-file and database-credential loading so
the library runs under the Climate TRACE pipeline and on Azure, and fixed a
`pd.NA` gas-capture crash alongside SDST landfill open/close-year handling.

## Added

- New `SWEET_python.singapore_k` subpackage exposing `compute_singapore_k`,
  which holds the standalone Singapore (Wang et al. 2024) decay-rate `k`
  calculation — the composition lookup array (bs/bf/nb) plus the temperature
  and moisture factors. ([#14](https://github.com/RMI/SWEET_python/pull/14))
- `iso3.csv` resolver (`defaults_2019._find_iso3_csv`) that locates the country
  lookup table by checking the package directory, then the Climate TRACE static
  data cache (`STATIC_DATA_CACHE_DIR`), then an `ISO3_CSV_PATH` environment
  override — so the country/region defaults load in the pipeline and not just
  in local dev. ([`5edaca5`](https://github.com/RMI/SWEET_python/commit/5edaca5))

## Changed

- Extracted the Singapore `k`-value method out of the `City` parameters class:
  `city_params` now imports and delegates to
  `singapore_k.compute_singapore_k(waste_fractions, temperature, precip, ...)`
  rather than computing the lookup array and temperature/moisture factors
  inline. ([#14](https://github.com/RMI/SWEET_python/pull/14))
- Database connection setup in `import_basics_site` now reads credentials from
  environment variables — accepting both lowercase `host`/`port`/`user`/
  `password`/`dbname` and Azure-style `DB_HOST`/`DB_PORT`/`DB_USER`/
  `DB_PASSWORD`/`DB_NAME` — only loads the local `.env` file when those are
  absent, and raises a clear error when credentials are still missing — making
  the weather-table queries portable off the original developer machine.
  ([`b7e9f7c`](https://github.com/RMI/SWEET_python/commit/b7e9f7c))
- Packaging now uses `find_packages()` in `setup.py` so the new `singapore_k`
  subpackage is included in installs (previously only `SWEET_python` itself was
  packaged). ([`d9bdb3c`](https://github.com/RMI/SWEET_python/commit/d9bdb3c))

## Removed

- Deleted the stale committed `q_df.csv` artifact (733 rows).
  ([`854c822`](https://github.com/RMI/SWEET_python/commit/854c822))

## Fixed

- Gas-capture presence check no longer crashes on missing data: a `pd.NA`
  value is now treated as "no capture" instead of triggering the "boolean value
  of NA is ambiguous" error, so oxidation defaults to the no-capture value for
  the site type. ([`6384a17`](https://github.com/RMI/SWEET_python/commit/6384a17))
- SDST/TRACE projection path now zeroes baseline and scenario waste masses
  outside the new landfill's open/close years, so disposal is only counted
  while the site is actually operating.
  ([#13](https://github.com/RMI/SWEET_python/pull/13))
- Replaced the hardcoded local OneDrive path to `iso3.csv` with a
  package-relative path so the country lookup resolves wherever the package is
  installed. ([`854c822`](https://github.com/RMI/SWEET_python/commit/854c822))

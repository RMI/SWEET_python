# SWEET_python Changelog — May 2026

**Highlights:** SDST (the `sdst_v1_5` advanced single-site path) can now model from a landfill's actual open year — supported range 1950–2050 — instead of a hardcoded 1990 start, with new validation of open/close, waste-mass, and implementation years. The month also adds a Central Asia disposal default (fixing Afghanistan), wires up automatic Jira-ticket creation for new GitHub issues, and cleans up unprofessional code comments.

## Added

- New GitHub Actions workflow that fires on `issues: [opened]`, builds a JSON payload, and POSTs to a Jira automation incoming webhook (`JIRA_WEBHOOK_URL`, with an `X-Automation-Webhook-Token`) to create a ticket whenever an issue is opened in the repository.
  ([#19](https://github.com/RMI/SWEET_python/pull/19))

## Changed

- SDST no longer hardcodes a 1990 model start year. The advanced single-site decision-support path (`City.sdst_v1_5`) now derives the model start from each landfill's actual open year (supported range 1950–2050): it reindexes and forward- and back-fills the waste-fraction vectors onto that span and rebuilds the waste-mass vectors over the same span, so landfills opened before 1990 accumulate pre-1990 waste history. Added validation of landfill open/close years, waste-mass year, and implementation year (raising `INVALID_PARAMETERS` on out-of-range inputs or a close year before the open year), updated `model_v2`'s emissions loop to use the caller-supplied year range starting at the open year (rather than `max(open_date, 1990)`) and to index waste mass by that range, and added regression tests covering both the legacy 1990-start behavior and the new pre-1990 history.
  ([#21](https://github.com/RMI/SWEET_python/pull/21))
- **WP-290:** Replaced unprofessional inline code comments across `city_params.py`, `defaults_2019.py`, and `singapore_k/singapore_k.py` with neutral, professional wording (no modeling behavior changed).
  ([#22](https://github.com/RMI/SWEET_python/pull/22))

## Removed

- **WP-290:** Deleted dead, commented-out code — a disabled scenario/baseline waste-mass ratio adjustment block for diverted (compost/anaerobic/recycling/combustion) masses in `city_params.py`, and a stale commented-out `mef_compost` default in `defaults_2019.py`.
  ([#22](https://github.com/RMI/SWEET_python/pull/22))

## Fixed

- **WP-264:** Added Central Asia (and Rest of Oceania) entries to the disposal-fraction defaults so Afghanistan resolves to a valid default instead of falling back to NaN; both regions are set to fully open-dumped (`fraction_open_dumped = 1.0`, `fraction_landfilled = 0.0`).
  ([#18](https://github.com/RMI/SWEET_python/pull/18))
